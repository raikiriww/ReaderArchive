# 搜索评测使用与标注记录

## 安全运行

完整容器评测：在仓库运行 `bash scripts/run_semantic_eval.sh`。脚本固定使用独立 compose 项目、服务、镜像和数据目录；有失败会先写完报告，再以非零状态结束。不要将这份配置指向日常使用的数据。

`seed` 会清空合成资料，因此同时要求：

- 数据库名必须是 `reader_semantic_eval`，主机只能是 `eval-db` 或本机回环地址。
- `READER_ARCHIVE_DIR` 必须是容器 `/app/eval-data/archive` 或仓库的 `.local_eval/reader-semantic/data/app/archive`。
- 必须显式设置 `READER_EVAL_ALLOW_RESET=isolated-semantic-eval`。
- 库内不得有任何不属于固定合成资料的存档 ID。删除文件时只删除固定资料对应的 HTML。

`run` 只登录、查询并输出结果，不会灌数据。支持当前分页返回以及旧数组返回。默认访问 `/api/v1/archive-search`；`READER_EVAL_SEARCH_ENDPOINT` 可以指定旧服务的查询入口。**新版程序的旧入口已经转到新检索，不能用它代表旧检索基线。**

`READER_SEMANTIC_SEARCH_ENABLED=false` 可用于独立正文关键词基线；开启模型后的 seed 走正式应用的同一个正文提取、分段和索引过程。评测不另写一套更容易通过的索引。

## 指标含义

这是一组 34 篇人工资料、31 个固定问题的回归样本，不是来自真实用户的独立质量验收集。不要把这组分数外推为实际资料库上的准确率。

- 明确目标（标题、短词、原句、边界例）：指定主目标必须第一。
- 主题问题（改写问题、中英文提问）：任意已经标为相关、能回答问题的文章可以第一。
- 两类问题都检查返回前五条里的相关比例和预期文章召回。返回一个可靠结果比凑满五个好；空位不当成无关文章，漏掉已标相关文章仍降低召回。
- 重复文章不重复得分，错误首位不能被“目标在前三”掩盖。
- 原文证据例检查返回片段确实含尾段/短词。只返回正确文章开头仍失败。
- 无答案问题要求零结果。报告单列误报，不与正常问题平均掩盖。
- MRR@10、NDCG@10、平均耗时和 p95 单列。高 NDCG 不能替代前五相关比例，因为相关目标后面的无关结果不会明显降低 NDCG。

当前严格整题通过要求前五没有不相关文章、预期文章全部在前五，故比一般产品上线门槛更严。失败需要审查具体结果，不应为了通过随意添加相关标签。`--fail-on-regression` 会报告后返回失败状态，适合明确要求整组通过的自动检查。

## 2026-09-05 标注复核（v3-reviewed）

旧的 expected 元组同时被当作“所有相关文章”与“唯一正确顺序”，两种含义并不一致。本轮阅读全部合成正文后作如下修订，并将同样规则应用到旧、新检索结果；保留原始报告用于审计。

1. 主题问题接受任一已标相关答案排第一。例如“向量数据库能不能放在本地跑”中，`local-llm-cost` 原来就在 expected 中，且正文直接提出并回答这个问题，不应该因它超过 `pgvector-search` 排第一而判错。明确文章找回仍要求原目标第一。
2. “放假”补标 `semantic-short-word`：正文真实包含该词，并以它为短词检索示例。关键词检索应允许这个正文命中，主要目标仍是 `work-ai-vacation`。
3. “员工因为 AI 变高效后应该获得什么福利”补标 `english-ai-workweek`：正文明确讨论生产率应转成更短工作周、灵活安排和员工福利。
4. “稍后读和订阅源整理”补标 `mixed-rss-ai`：正文明确讨论收集订阅源、归档文章、判断稍后阅读。
5. “local vector database for semantic search”补标 `local-llm-cost`：正文讨论本地模型和本地向量数据库存放文章片段及查询、离线检索个人存档；这是合理的跨语言答案。

仅出现 AI 的沟通文章、Google 历史、Go 并发笔记、单纯音乐现场评论等，不能据此视为工作周问题、搜索交互验证、稍后读整理或行程问题的有用答案；这些结果继续降低相关率。

旧基线从当前修改前的 Git HEAD 导出到临时目录，在独立 `reader_semantic_baseline` 数据库使用旧的正文提取、旧分段、旧索引和旧检索完整运行；新方案使用独立 `reader_semantic_eval`。两边共享同一本地模型文件、Python 依赖和合成资料，数据库和服务端口隔离。
