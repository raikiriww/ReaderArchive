# 搜索后端实施与验收记录

> 历史阶段记录，包含当时的方案、结果和未完成项。当前实现及最终验收以 [CPU 搜索升级](search-cpu-upgrade.md) 和 [发版验收](release-acceptance-20260905.md) 为准。

2026-09-05。本文供开发验收；检索质量与候选模型对照见 [search-upgrade-evaluation.md](search-upgrade-evaluation.md)。本次使用隔离 PostgreSQL 与合成资料，未清空或重建用户真实资料库。

## 实现范围

- 新增 `reader_archive_search_documents`，完整可读正文、来源文件、提取版本、覆盖状态独立于模型保存。正文提取与向量生成有独立后台队列；模型慢启动、忙碌或失败不阻塞其他文章的正文准备。
- 修复空行被抹平、短尾段丢失和单字文本丢失。正文使用连续范围切块；真实模型使用其 tokenizer 计数，为标题与特殊符号预留输入预算，逐段覆盖原文。标题截短仅作用于模型前缀，不截短存储的原始正文或文章标题。
- 新增 `GET /archive-search` 与 `GET /archive-search/{task_id}/text`。原 `GET /archive-tasks?q=...` 和 `title=...` 也走新检索路径，保留原列表默认未读、不合并任务、元数据命中 `search_match=null` 的兼容行为。
- 范围在召回之前生效：已读、标签、来源、保存日期、内容类型。语义检索先在指定任务集合精确计算、每文章选一个最佳片段，再限制候选文章数，避免长文章占满片段名额及筛选后漏掉候选。
- 关键词从独立正文及原始标题、自定义标题、视频标题、标签、网址召回。SQL 使用转义后的字面匹配，最终校验英文短词边界、全部显式词及引号连续短语。`Go` 不匹配 `Google`，`AI` 不匹配 `daily/email`；短标识符和 `C++`、`.NET` 等符号标识不自动进行语义扩展。
- 整个标题、原文短语与全部显式词优先；其它候选按词法名次与语义名次融合，不把余弦分数加几个无量纲加分当置信度。中文二字补漏需要保守覆盖率，但仍标为 `possible`；纯语义也标为 `possible`。有完整字面证据的结果标为 `strong`。这些标记说明命中依据，不保证文章能回答整个问题。
- 新搜索严格按完整原 URL 合并，代表项来自实际命中的版本；返回版本数与任务 ID。同标题或不同查询参数的 URL 不合并。旧任务列表保持每次保存单独一项。
- 返回原文摘要、匹配类型、来源文件、段落位置及段内高亮。摘要命中前最多保留 40 个字符，不为凑长度回退到无关铺垫。`highlights` 和 `paragraph_highlights` 都是 Unicode codepoint 范围，前端用 `Array.from`，不是 UTF-16 索引。长段落可以精确滚到实际命中文字。
- 正文阅读端点只返回提取后的原文，不生成回答；文件不存在、正文尚不可读时不伪造阅读内容。预览不自动标已读。

## 迁移与运行兼容

`20260905_0009` 新增正文表，先把原有片段按顺序复制为过渡正文，不删除旧向量。过渡记录为 `legacy-v1`，仍可按词查及阅读，但覆盖统计算 `pending`；后台提取完整原文后切为 `readable-v2/ready`。单篇新向量在事务中替换，失败时完整关键词正文保持可用。

向量文本版本默认为 `token-body-v2`。文章标题加入 document hash，自定义标题改动会触发重算；查询按当前文本版本与 hash 关联，避免把旧切块混进新结果。启动只排后台任务，正文提取不等待全部模型重建。

默认项进入应用配置，现有 compose 不需要新增字段。沿用当前镜像内置的本地 MiniLM、384 维数据库列。模型没有自动切换，也没有新增外部服务或数据库扩展。迁移不支持破坏性降级；备份恢复策略沿用项目部署规范。

| 默认配置 | 用途 |
| --- | --- |
| `semantic_text_version=token-body-v2` | 使旧向量进入后台重新整理 |
| `semantic_query_lock_timeout_seconds=0.15` | 模型正忙时，查询最多等锁 150ms，随后返回关键词结果 |
| `semantic_retry_interval_seconds=60` | 队列空闲时限频检查缺失和失败记录，模型恢复后自动补齐；即使没有待索引文章也会重试模型预加载 |
| 查询向量缓存最多 128 条 | 同一运行进程内反复筛选或返回时复用查询向量 |
| `semantic_search_limit=120` | 有限的语义候选**文章**数，已不再是全库片段数 |
| `semantic_min_score=0.34` | 保留旧模型召回下限，未凭小样本统一抬高阈值 |

查询不在请求线程中启动冷模型，冷启动直接给关键词结果。独立模型后台预加载；已开始的模型运算不会被强杀。路由把同步检索移至线程中，主事件循环保持可响应。锁等待预算不等于模型运算或数据库查询的总耗时保证。

`total_is_exact=false` 表示组合搜索总数包含有限语义候选，不能当成全库所有相似内容的精确计数；纯关键词总数可准确计算。

## 实际检查

- 完整后端回归：**120 passed，64.07 秒**。之后针对冷模型回退、高亮词边界与实际定位等改动复测新旧搜索：**29 passed，14.84 秒**。最后模型冷启动空库恢复等全部新增搜索专项：**22 passed，4.98 秒**；120 条全量成绩不冒充包括这些最后新增用例。
- 新业务文件与改动业务文件通过 Ruff；`search.py / semantic.py / service.py / crud.py / models.py` 通过 Mypy。
- 专项覆盖：900 字首段后 50 字尾段、多段空行、真实输入预算、长段落末尾片段与位置、Emoji 前缀高亮、Go/AI/C++/.NET 干扰、引号约束不被语义绕过、模型故障下正文可搜、模型恢复后自动重试、正文队列不被模型队列阻塞、模型锁限时、旧版正文迁移保留、pending/unavailable 区分、同 URL 版本合并与参数 URL 区分、自定义标题修改后重算且原视频标题仍可查。
- 测试运行有既有 HTTP 客户端弃用提示，以及部分非搜索子进程测试在事件循环结束时的资源清理警告；没有测试失败。未为掩盖警告修改归档子进程逻辑。
- 实际当前本地模型另由主任务检查：565 字中文输入被分为 3 段，每段输入不超过 128 tokens，企鹅与数据库两种尾段均保留并生成了不同的尾部向量。不能据此声称整体语义相关性已达标。

## 1,000 / 10,000 篇抽样性能

在开发机的隔离 PostgreSQL 中，每篇写入约 2,200 个中文字符、独立 URL、无标签；一篇含独有尾词“企鹅栖息地”，全部标题包含“备份”。关闭语义、`exact=true`，每次取默认第一页，三次顺序调用测服务端耗时。此表是本次优化后抽样，**不是家用服务器的 p95 发布门槛验证**，未计浏览器网络，未模拟大量并发。

| 文章数 | 查询 | 总匹配 | 三次耗时 ms |
| --- | --- | --- | --- |
| 1,000 | 企鹅栖息地 | 1 | 58.8 / 43.8 / 44.2 |
| 1,000 | 备份 | 1,000 | 75.9 / 73.0 / 76.1 |
| 10,000 | 企鹅栖息地 | 1 | 375.4 / 341.9 / 341.0 |
| 10,000 | 备份 | 10,000 | 511.4 / 464.4 / 514.0 |

优化前，10,000 篇全部匹配标题的查询为 1,253–1,333ms。主要改进是元数据与正文分别作候选判断，以及有明确中文标题命中时不传输所有候选的完整正文；最终只把本页任务转成完整响应。

常见词查询仍接近/略超过 0.5 秒初始预算，真实更长文章、大量标签、并发归档/检索、10,000 篇向量候选的负载仍须独立测量。当前语义精确扫描优先保证筛选召回；大规模部署后可能需要迭代 ANN 或其它索引优化。

## 尚未实施的边界

- 当前是 PostgreSQL 上的字面候选与应用内排名；**不是**已建好专用中文分词全文索引、BM25 或完整中文查询理解。没有宣称普通 `ILIKE` 等价于全文索引。
- 没有 OCR、视频字幕转录，也没有 PDF 原始页码定位。无可读正文会明确计为不可用；阅读位置来自提取后的原文段落。
- 没有额外重排模型、问答生成或经独立留出集校准的模型阈值。语义相近候选仍有噪声，交由可展开的“可能相关”区呈现；保留真实原句让用户核对。
- 没有全库跨版本原子激活和永久双份向量：新段落按文章事务替换，旧关键词过渡正文在后台回填期间可用。更换维度仍需另行迁移，不能仅修改模型名字。
- 性能抽样与小型固定查询集都不能替代设计评估中提出的真实用户查询与目标机器验收。候选模型对照未支持更换默认模型，详见评测文档。
